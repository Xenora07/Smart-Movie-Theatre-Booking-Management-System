# DBMS Microproject Viva Notes

## Explain the architecture
The React frontend sends HTTP requests through Axios. The Spring Boot backend receives requests through REST controllers, applies business logic in services, and uses Spring Data JPA repositories to read/write MySQL. Responses return as JSON to React.

## Why exactly nine tables?
The nine tables represent customers, movies, theatres, screens, seats, shows, bookings, booking-seat allocations, and payments. Authentication is represented within CUSTOMER, so a separate USER table is not required for this scope.

## Primary and foreign keys
- A primary key uniquely identifies a row.
- A foreign key ensures a referenced record exists.
- Unique constraints enforce business rules such as unique customer email and one seat allocation per show.
- CHECK constraints can validate values such as positive prices and valid ratings, subject to MySQL version/behavior.

## Why BOOKING_SEAT?
A booking can include multiple seats, and a seat is used by many bookings over time. BOOKING_SEAT resolves the many-to-many relationship and scopes each allocation to a show.

## Why does BOOKING reference SHOW?
It explicitly identifies the show being booked, makes booking history easier to query, and enables the service to validate that every selected seat belongs to the screen hosting that show.

## What is a transaction?
A transaction groups related database operations into one atomic unit. If seat allocation fails partway through, the booking must roll back rather than leave partial data.

## How is double booking prevented?
The backend validates availability inside a transactional workflow, while a database unique constraint on (show_id, seat_id) is the final defense against two concurrent requests allocating the same seat for the same show.

## Why hash passwords?
A password hash avoids storing plaintext passwords. Login verifies the submitted password against the hash. The hash must never be sent back to the frontend.

## Why simulated payments?
The microproject demonstrates payment records and status relationships without collecting real card details or depending on an external payment gateway.
